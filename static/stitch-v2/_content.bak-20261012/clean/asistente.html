En arquitectura de sistemas operativos concurrentes, ambos son primitivas de sincronización para controlar el acceso a regiones críticas, pero su semántica de propiedad difiere sustancialmente.

lock Mutex (Mutual Exclusion)

Mecanismo de bloqueo con dueño. Solo el thread exacto que adquirió el lock con pthread_mutex_lock() está autorizado a liberarlo.

traffic Semáforo Contador

Mecanismo de señalización entero no negativo. Cualquier thread puede emitir un sem_post() para desbloquear a otro hilo en espera.

Concepto base Mecanismo de bloqueo binario Señalización entera (conteo de recursos)

mutex_vs_sem_posix.c 
// 1. MUTEX: Exclusión mutua estricta
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

pthread_mutex_lock(&lock);
saldo_cuenta += deposito; // Sección crítica segura
pthread_mutex_unlock(&lock);

// 2. SEMÁFORO: Control de capacidad concurrente
sem_t sem_slots;
sem_init(&sem_slots, 0, 5); // Máximo 5 hilos simultáneos

sem_wait(&sem_slots);  // Decrementa contador
procesar_peticion_http();
sem_post(&sem_slots);  // Incrementa y notifica al scheduler
Condición de Deadlock (Coffman)

El interbloqueo ocurre si y solo si se cumplen las cuatro condiciones simultáneamente:

C(Deadlock) = Exclusión Mutua ∧ Retención y Espera ∧ No Expropiación ∧ Espera Circular
